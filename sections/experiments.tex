\section{Experimental Setup}
\label{sec:experiments}

\subsection{P4D-Bench}
\label{sec:benchmark}

The benchmark summary in \cref{fig:dr_agentos_overview} reports the full
\pfdbench{} release: 54 scenes, 90 scene-days, 239.19k dynamic state
changes, and 803.68k task instances. The task pool comprises current-state
prediction (16\%), object navigation (27\%), vision-and-language navigation
(29\%), and question answering (28\%). The controlled experiments below
focus on prediction and ObjectNav together with EQA diagnostics; the
navigation-focused subset is further decomposed into N1--N4, with N5 used
as a cross-scene evaluation subset.

\paragraph{Dynamic household construction.}
\pfdbench{} is built from continuous household histories, not independently
sampled placements.  We derive activity priors from longitudinal smart-home
records such as CASAS \citep{cook2013casas} and ARAS, and action--object
evidence from EPIC-KITCHENS-100 and OPPORTUNITY.  These records provide
statistics rather than trajectories copied into simulation. Across 54 HSSD
scenes \citep{khanna2024hssd} and 90 generated scene-days, we freeze resident
schedules, room preferences, orderliness, object ownership, and placement
habits, then jointly generate activities, resident region trajectories, and
object transitions.
Frozen distributions make earlier days predictive of later ones, while
sampled events and exceptions prevent deterministic scripts.  The audited
configuration yields 42.6 region transitions per resident-day, 6.56
relocations per personal object-day, 52.6\% within-region relocations, and
zero terminal collisions.  Unsupported parameters are explicitly marked
as benchmark-authored.

\paragraph{Object-specific dynamics.}
Each target follows one of four causal mechanisms
(\cref{tab:mobility-regimes}).
Every relocation is attributable to an activity, resident transition, or
tidying event.  Routine objects follow activity chains; personal objects
follow a placed/carried lifecycle with owner-specific drop habits; and
irregular destinations depend only on affordance.  Audits verify that
personal objects do not merely track their owners and that activity or
actor identity does not predict irregular destinations beyond affordance.

\paragraph{Physical realization and partial observation.}
Generated transitions are replayed chronologically in Habitat; only
semantically valid, collision-free placements with reachable inspection
viewpoints enter the benchmark.  A robot patrols using the map, time, travel
cost, and its own history, never current object states, resident locations,
hidden activities, or generator latents.  Region visits produce local
snapshots from which observations are derived.  For a target and query time,
the public input contains only the preceding observations, last-seen state,
staleness, calendar context, and legal candidates.  Query times cover both
the natural distribution and mechanism-relevant windows, such as stages of
a routine or the interval after a personal object is dropped.  Current state,
hidden transitions, activities, and mobility labels remain private.

\paragraph{From prediction to navigation.}
The prediction track first evaluates the region/receptacle belief without
navigation confounds.  Each navigation episode then reuses the same query
and adds a start pose, inspection viewpoints, and a budget.  N1 tests the
Top-1 goal, N2 tests cost-aware search under the full belief, and N3 tests
evidence-aware posterior updates and replanning.  N4 adds execution-time
target motion, while N5 evaluates held-out scenes or households.  All
methods share candidates, starts, geometry, control, and budgets; only the
belief and resulting search order differ.

The full benchmark additionally provides vision-and-language navigation
instances over the same evolving histories. They exercise the common memory
interface under language-conditioned goals, but are not included in the
navigation-focused causal comparisons reported below.

\paragraph{Splits and quality control.}
We split complete temporal sequences rather than individual queries and
reserve disjoint homes for generalization.  Audits check future leakage,
causal continuity, mobility behavior, physical validity, and patrol
independence.  Results are stratified by mobility regime, transition class,
staleness, and spatial difficulty; full statistics and audit thresholds are
provided in the supplement.



\subsection{Baselines and Ablations}
\label{sec:baselines}

We compare against four baseline families under identical candidate
states, inspection viewpoints, perception inputs, path planner, and
navigation budgets.

\emph{Non-predictive} baselines include Last Seen and Nearest Candidate
Search.
\emph{Statistical} baselines include Frequency Prior, first-order Markov
transitions, time-conditioned transitions, and an instance-hotspot prior.
\emph{Learned} baselines include GRU Direct, Transformer Direct,
Scene Graph Memory \citep{kurenkov2023dynamic}, a PredictiveGraphs-style
filter \citep{saavedraruiz2026predictivegraphs}, and a FlowMaps-style
future-location model \citep{argenziano2026flowmaps}.
Where an external method assumes a different state space, we project its
prediction onto the same benchmark candidate set and rank candidates by
predicted probability mass, isolating differences in belief estimation
rather than downstream planning.

N4 additionally compares against Transit-Aware Planning under its
required online target-path input \citep{dorbala2026portable}.
Oracle Current State provides the navigation upper bound.
Oracle Activity supplies the ground-truth current activity and is
reported only as a diagnostic rather than as a fair baseline.

For EQA, all methods are evaluated using the same question templates,
answer ontology, and answer normalization.
The queried information must be recovered from the memory state available
to each method.
When a learned language readout is required, the readout is held fixed
across compared memory methods so that EQA primarily measures memory
quality rather than differences in language-model capacity.

The principal ablations remove:
continuous-time features;
the persistence--relocation factorization;
instance-specific history;
calendar context;
negative evidence;
visibility calibration;
Bayesian belief updating;
or the full belief distribution in favor of Top-1 prediction.
\emph{P4D-Belief Prior} predicts once and searches without belief updates,
while full \pfdnav{} closes the observe--update--replan loop.


\subsection{Metrics}
\label{sec:metrics}

We first evaluate the predictive belief independently of downstream
navigation using state Top-1/Top-$k$ accuracy, negative log-likelihood
(NLL), Brier score, expected calibration error (ECE), true-state rank,
mean reciprocal rank (MRR), and persistence AUROC.

For navigation, we report Success Rate (SR), SPL, path length,
completion time, First-Go SR, number of inspected candidates, and search
cost.
N3 additionally reports Recovery SR after an incorrect first prediction
and posterior true-state rank improvement after negative evidence.
N4 reports Online Recovery SR, replanning count, replanning delay, and
excess path length relative to a trajectory-aware oracle.
The trajectory-aware oracle is used because a moving target makes the
conventional shortest path to a fixed terminal goal ill-defined.

For EQA, we report answer accuracy broken down by existence, location,
temporal, activity, count, comparison, and reasoning questions.
For questions with structured answer spaces, predictions are normalized
to the benchmark ontology before scoring.
We additionally report category-macro accuracy so that frequent
question types do not dominate the aggregate EQA score.

All aggregate results include bootstrap confidence intervals over
episodes and both micro averages and mobility-type macro averages.
Results are stratified by world variant, mobility type, transition class
(\emph{stay}, \emph{same-region move}, \emph{cross-region move},
\emph{multi-move}, and \emph{return}), staleness interval, spatial
difficulty, grounding quality, and generalization split.
For EQA, results are additionally stratified by question type.

The key causal contrast is the paired routine gain: the improvement of a
method in the routine world relative to its performance under the paired
static and random variants.
This contrast tests whether gains arise from exploiting persistent
temporal regularities rather than from scene geometry, object identity,
or generic search behavior.

Implementation and reporting details are provided in
\cref{app:implementation,app:protocol}.
