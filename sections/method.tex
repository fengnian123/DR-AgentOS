\section{Problem Formulation and System Overview}
\label{sec:problem_overview}

\subsection{Long-Horizon Embodied Task Setting}
\label{subsec:problem_setting}

\paragraph{Persistent embodied cognition.}
Real-world embodied tasks are only partially observable: a robot sees a limited field of view, acts over horizons much longer than a single observation, and revisits an environment whose objects, access conditions, and task-relevant states may have changed. A static map can support localization, but it cannot by itself distinguish a persistent fact from a transient observation or determine whether an old route is still traversable. We therefore formulate long-horizon operation as \emph{persistent embodied cognition}: the robot must maintain a temporally grounded world state while using that state to decide what to observe and do next.

\paragraph{Multimodal observations.}
At decision round $t$, the available multimodal observation is
\begin{equation}
    \mathbf{o}_t = \left\{
    \mathbf{I}_t,\mathbf{D}_t,\mathbf{L}_t,\mathcal{G}_t,
    \boldsymbol{\xi}_t,\tau_t
    \right\},
    \label{eq:multimodal_observation}
\end{equation}
where $\mathbf{I}_t$ and $\mathbf{D}_t$ are RGB and depth observations, $\mathbf{L}_t$ denotes LiDAR or other geometric measurements, $\mathcal{G}_t$ denotes available 3D Gaussian Splatting (3DGS) scene evidence, $\boldsymbol{\xi}_t$ is the robot pose, and $\tau_t$ is the timestamp. The set-valued representation allows the system to operate with the subset of modalities available on a particular platform.

\paragraph{Task-conditioned decision making.}
Let $\mathcal{T}$ denote the natural-language task, $\mathbf{s}_t$ the current robot and execution state, $\rho_t$ the active task stage and its completion conditions, $\mathcal{Z}$ the set of callable tools, and $\mathcal{M}_t$ the persistent world memory. The Agent Controller first constructs a task-conditioned query and then selects a tool and an executable action:
\begin{align}
    \mathbf{q}_t &= \mathcal{Q}(\mathcal{T},\rho_t,\mathbf{s}_t),
    \label{eq:query_construction}\\
    (z_t,\mathbf{a}_t) &= \Pi\!\left(
    \mathcal{T},\rho_t,\mathbf{s}_t,
    \mathcal{R}(\mathcal{M}_t,\mathbf{q}_t),\mathcal{Z}
    \right),
    \label{eq:controller_decision}
\end{align}
where $\mathcal{Q}$ constructs the query, $\mathcal{R}$ retrieves task-relevant memory, $z_t\in\mathcal{Z}$ is the selected tool, $\mathbf{a}_t$ is its command or argument, and $\Pi$ denotes the controller policy. Equations~\eqref{eq:query_construction} and~\eqref{eq:controller_decision} specify the information available to the controller; they do not assume that $\Pi$ is learned or end-to-end differentiable.

\subsection{Closed-Loop DR-AgentOS Architecture}
\label{subsec:system_overview}

\paragraph{From a static pipeline to an evolving world model.}
\dragentos{} realizes Eq.~\eqref{eq:controller_decision} as a closed cognitive loop rather than a fixed perception--navigation pipeline. Multimodal observations are first grounded into a 4D World Memory. Task-conditioned retrieval then exposes relevant entities, relations, states, and historical evidence to the Agent Controller, which decomposes the goal and invokes tools through the Tool Manager.

\paragraph{Action, verification, and memory evolution.}
Execution results are evaluated against both task completion conditions and prior memory. When new evidence disagrees with stored knowledge, the system invokes Reflection before committing a memory update. The resulting perception--memory--reasoning--action--reflection--update cycle makes experience persistent: action changes the world model, and the revised world model conditions subsequent action.


\section{Alternative Draft B:DR-AgentOS Framework}
\label{sec:framework}

\subsection{Persistent Embodied Task Setting}
\label{subsec:problem_setting}

Real-world embodied tasks require an agent to operate under partial
observability over horizons much longer than a single perception cycle.
The robot observes only a local portion of the environment, while objects,
access conditions, traversability, and other task-relevant states may change
between observations or repeated visits. Execution is also inherently
stateful and uncertain: a planner may successfully return a route without the
robot reaching the destination, and reaching a candidate location does not
necessarily imply that the intended object or state has been verified.

These properties make a one-shot
``instruction--tool call--response'' pipeline insufficient for persistent
robot operation. Long-horizon embodied execution requires the agent to
maintain both task state and world state, use previous experience to ground
new decisions, and revise its plan when physical outcomes differ from what was
expected.

We therefore formulate \dragentos{} as a persistent embodied system operating
over an evolving world model. At time $t$, the system maintains the user task
$\mathcal{T}$, the current robot and execution state $\mathbf{s}_t$, an active
task plan $\mathcal{P}_t$, a set of available embodied capabilities
$\mathcal{Z}$, and a persistent 4D World Memory $\mathcal{M}_t$. Rather than
predicting a complete action sequence in advance, the system repeatedly
retrieves relevant world state, selects and executes a grounded operation,
evaluates its physical outcome, and updates the task or world state when
supported by new evidence.


\subsection{System Overview}
\label{subsec:system_overview}

\dragentos{} is organized around two tightly coupled components: a
\emph{Closed-Loop Agent Harness} that manages task execution and a
\emph{4D World Memory} that maintains persistent knowledge of the evolving
environment. The former connects high-level reasoning to embodied tools and
execution backends, while the latter provides spatial, semantic, temporal,
and historical grounding for planning and verification.

Given a user instruction, the Agent Harness maintains a lightweight task plan
and repeatedly determines the next operation to perform. Before each decision,
task-relevant information is retrieved from the 4D World Memory and combined
with the current robot state, recent observations, and execution history.
Selected capabilities are then dispatched through a standardized execution
interface to deterministic modules, simulation environments, or physical
robot controllers.

The resulting observations and execution status are not treated as successful
task progress by default. Instead, they are checked against the expected
effect of the action and the completion conditions of the current subgoal.
Verified outcomes update the task state and may be committed to persistent
memory, whereas failures or ambiguous observations can trigger retries,
additional sensing, or replanning.

This organization gives rise to two coupled feedback loops. The
\emph{execution loop} connects planning, execution, verification, and recovery.
The \emph{memory loop} converts grounded observations and verified outcomes
into persistent world knowledge that can influence later decisions and future
tasks. Together, these loops allow \dragentos{} to reason and act over a world
model that evolves with continued robot operation.


\subsection{Closed-Loop Agent Harness}
\label{subsec:agent_harness}

The Agent Harness provides the runtime abstraction between high-level
reasoning and embodiment-specific execution. It consists of six cooperating
components: the \emph{Orchestrator}, \emph{Context Manager},
\emph{Skill/Tool Registry}, \emph{Execution Runtime}, \emph{Verifier}, and
\emph{State Commit}. Their interaction forms a repeated
plan--execute--verify--commit cycle rather than allowing a language model to
invoke robot actions directly.

The \emph{Orchestrator} interprets the user goal, maintains the current task
plan, and selects the next operation according to unresolved subgoals and
execution feedback. The plan remains lightweight and revisable: new
observations, tool failures, or changes in the environment can alter subsequent
steps without requiring the entire task to be planned again from scratch.

The \emph{Context Manager} provides the information needed for each reasoning
step. Instead of exposing the full accumulated history to the controller, it
constructs a task-conditioned context from three sources: relatively stable
resident information such as system policy and available capabilities,
refreshed information such as robot state and recent observations, and
accumulated task information such as plan progress, tool results,
verification results, and recovery traces. Relevant evidence retrieved from
the 4D World Memory is injected into this context when required by the current
decision.

Executable capabilities are exposed through the \emph{Skill/Tool Registry}.
We distinguish an atomic \emph{tool}, which performs a typed computation or
embodied operation, from a higher-level \emph{skill}, which may compose
multiple tools together with explicit completion conditions and recovery
logic. Representative tools include spatio-temporal memory retrieval,
semantic object search, route planning, exploration-state query, and
inspection. This abstraction allows the Orchestrator to reason over a stable
capability interface without depending on the internal implementation of each
backend.

Selected calls are dispatched through the \emph{Execution Runtime}. Before
execution, the runtime validates the call schema, checks capability
availability and task-dependent preconditions, applies runtime and safety
constraints, and routes the request to the corresponding backend. A backend
may be a deterministic built-in module, a navigation planner, a simulator
adapter, or a learned robot controller. Execution returns a structured
\texttt{ExecutionReceipt} containing the resulting observation, status,
latency, and failure information.

The \emph{Verifier} determines whether the returned evidence actually supports
task progress. Verification can be applied at action, subgoal, and task level.
This distinction is important because successful execution of a software
module is not equivalent to successful completion of its embodied objective.
For example, successfully computing a navigation path does not establish that
the robot has reached the target, and arriving at a target region does not
establish that the requested entity has been visually confirmed. Failed or
ambiguous verification may therefore trigger retry, re-observation, or
replanning before execution continues.

Verified transitions are passed to \emph{State Commit}, which provides the
boundary between transient execution evidence and persistent system state.
State Commit advances the active task plan, records verified execution events,
updates the current task context, and issues persistent-memory updates.
Contradictory or weak evidence can remain provisional instead of immediately
overwriting existing world knowledge.

This separation also defines the authority of different system components.
High-level models are responsible for semantic interpretation, task
decomposition, and capability selection, but they do not directly define the
physical world state. Entity identities and coordinates originate from the
mapping and memory modules, robot poses and execution outcomes originate from
the corresponding runtime backend, and persistent world-state changes are
committed only after verification. As a result, language-model reasoning is
grounded in source-derived state rather than being allowed to synthesize
unsupported physical facts.

The committed evidence is finally incorporated into the 4D World Memory and
becomes available to later context construction and task planning. The same
runtime can therefore continue execution, retry a failed action, acquire a new
viewpoint, replan around an environmental change, or reuse knowledge acquired
during previous tasks while preserving the provenance of the underlying world
state.


\section{4D World Memory}
\label{sec:4d_memory}

The 4D World Memory is the persistent cognitive substrate of \dragentos{}. We define ``4D'' not as a collection of timestamped frames, but as an \emph{executable world model} in which 3D semantic structure and temporal evolution are represented under a common identity system. It unifies geometry, semantics, topology, history, and source evidence so that the Agent Controller can reason about not only \emph{what} and \emph{where}, but also \emph{when}, \emph{whether it is still true}, and \emph{which observation warrants that belief}. This turns memory from a passive context cache into a world-authoritative system state shared by perception, planning, navigation, inspection, and reflection.

\subsection{Direct 3D Semantic Projection}
\label{subsec:grounding}

\paragraph{A geometry-authoritative world frame.}
All observations are synchronized by timestamp and registered through the robot pose into a common world frame. For an image coordinate $\widetilde{\mathbf{u}}=[u,v,1]^\top$ with valid depth $D_t(u,v)$, the corresponding world point is
\begin{equation}
    \mathbf{x}^{w}
    = \operatorname{proj}_3\!\left(
        \mathbf{T}_{w\leftarrow c,t}
        \begin{bmatrix}
        D_t(u,v)\mathbf{K}^{-1}\widetilde{\mathbf{u}}\\[1mm]1
        \end{bmatrix}
    \right),
    \label{eq:backprojection}
\end{equation}
where $\mathbf{K}$ is the camera intrinsic matrix and $\mathbf{T}_{w\leftarrow c,t}$ is the time-indexed camera-to-world transform. The same coordinate authority is shared by RGB-D observations, point clouds, meshes or 3DGS evidence, navigation nodes, and robot poses; semantic reasoning therefore remains anchored to coordinates that downstream tools can execute.

\paragraph{Semantics are lifted into the graph, not stored beside it.}
Open-vocabulary perception produces a semantic region, confidence, and visual descriptor \cite{liu2023groundingdino}. We lift this frame-local evidence into a 3D semantic observation and immediately project it into the world graph:
\begin{equation}
    \Pi_{\mathrm{sem}}:
    (\ell,\Omega,\mathbf{x}^{w},\tau,\mathcal{P})
    \longmapsto
    \Delta\mathcal{G}_{\tau},
    \label{eq:semantic_graph_projection}
\end{equation}
where $\ell$ is the canonical semantic class, $\Omega$ is the visual support, $\mathbf{x}^{w}$ is its 3D support, and $\mathcal{P}$ is the source provenance. The mapping either consolidates the observation into a persistent entity or instantiates a new graph node; its containment, proximity, and topological relations are then induced in the same coordinate frame. Thus, 3D semantics are not an auxiliary label layer attached after mapping: they are the primitive from which the semantic graph itself is incrementally constructed. This direct projection avoids the geometric information loss of first translating observations into free-form text and later attempting to recover executable structure.

\paragraph{Persistent identity through cross-view consolidation.}
Observations are consolidated according to semantic compatibility, 3D proximity, temporal consistency, and source confidence. Canonical class normalization absorbs vocabulary aliases, while metric support separates repeated instances of the same class. Persistent categories accumulate evidence across viewpoints; transient observations remain queryable evidence without being prematurely promoted to long-term facts. The result is an identity-preserving entity layer in which repeated observations strengthen a world hypothesis instead of multiplying disconnected detections.

\subsection{Time as a First-Class Memory Axis}

\paragraph{Causal materialization rather than frame accumulation.}
At decision time $t$, the agent materializes memory only from evidence observed no later than $t$:
\begin{equation}
    \mathcal{M}_{\leq t}
    = \operatorname{Materialize}
    \left(\Delta\mathcal{M}_{0},\ldots,\Delta\mathcal{M}_{t}\right).
    \label{eq:causal_materialization}
\end{equation}
This prefix-bounded construction makes time operational. It prevents future leakage during replay, scopes retrieval to the agent's actual experience, and allows any past decision point to be reconstructed with the evidence available at that moment. Time therefore governs memory visibility and causality rather than serving as display metadata.

\paragraph{Versioned identity and temporal validity.}
We represent the materialized memory as
\begin{equation}
    \mathcal{M}_{\leq t}
    =\left(\mathcal{G}_{\leq t},\mathbb{T}_{\leq t},\mathcal{B}_{\leq t}\right),
    \qquad
    \mathcal{G}_{\leq t}
    =\left(\mathcal{V}_{\leq t},\mathcal{E}_{\leq t}\right),
    \label{eq:memory_graph}
\end{equation}
where $\mathcal{G}_{\leq t}$ is the current semantic-spatial graph, $\mathbb{T}_{\leq t}$ is a set of temporally ordered world-state segments, and $\mathcal{B}_{\leq t}$ is an evidence and provenance bank. For entity $v_i$, a stable identity and its $k$-th state version are
\begin{align}
    v_i &= \left(i,\ell_i,\mathbf{p}_i,\mathbf{b}_i,\mathcal{N}_i,\pi_i^{\mathrm{cur}}\right),
    \label{eq:entity_record}\\
    h_i^{k} &= \left(
    [\tau_{i,\mathrm{start}}^{k},\tau_{i,\mathrm{end}}^{k}),
    y_i^{k},c_i^{k},d_i^{k},\mathbf{f}_i^{k},
    \mathcal{K}_i^{k},\mathcal{P}_i^{k}
    \right),
    \label{eq:state_version}
\end{align}
where $\pi_i^{\mathrm{cur}}$ points to the currently supported version. The validity interval expresses when a state is believed to hold; $y_i^k$, $c_i^k$, and $d_i^k$ encode state, confidence, and structured semantics; and $\mathcal{K}_i^k$ and $\mathcal{P}_i^k$ retain the visual and sensor provenance. Stable identity is consequently separated from mutable state: a doorway can remain the same entity while its accessibility changes, and a relocated object can preserve its history without forcing the system to choose between overwriting the past and duplicating the object.

\paragraph{World timelines as semantic change boundaries.}
When multi-view evidence confirms a persistent scene change, \dragentos{} seals the previous world-state segment and opens a new timeline in $\mathbb{T}_{\leq t}$. Timeline edges record the semantic transition, while stable entity identities link corresponding versions across segments. This provides a principled temporal abstraction between two extremes: treating every frame as a new world, or collapsing an evolving environment into a timeless map. Queries can address the active world state, a selected historical segment, or the change connecting them.

\subsection{Hierarchical Semantic Graph and Evidence Substrate}
\label{subsec:memory_hierarchy}

\paragraph{A multi-resolution world model.}
The semantic graph is organized as \textbf{Timeline--Floor--Room--Object}. Trajectory-supported places are consolidated into rooms; room transitions induce topological connectivity; and every 3D semantic entity is inserted into its containing room with metric and semantic relations to nearby entities. Relations such as \texttt{contains}, \texttt{near}, \texttt{connected-by}, and \texttt{has-entrance} allow the same memory to answer symbolic questions, ground spatial references, and produce executable navigation targets. Coarse-to-fine traversal lets the controller operate at the resolution demanded by the task without maintaining separate, mutually inconsistent maps.

\paragraph{Evidence-backed abstraction.}
Every graph assertion remains connected to an evidence ledger containing its observation time, source pose, sensor or rendered view, visual support, confidence, and content identity. Event-triggered keyframes preserve informative motion, semantic novelty, entrances, and region transitions, while redundant frames remain represented through compact temporal deltas. Structured captions and visual embeddings enrich retrieval, but never replace geometry or provenance. The graph is therefore both compact and auditable: high-level concepts remain traceable to the exact world-grounded observations from which they were formed.

\paragraph{Retention across memory timescales.}
Long-lived geometry and persistent entities form semantic memory; ordered observations and world-state segments form episodic memory; and unresolved, task-local hypotheses remain in working memory until verified. These are retention regimes over one shared graph, not isolated stores. Temporal validity, recurrence, semantic persistence, and task relevance jointly determine what is consolidated, what remains provisional, and what can be safely forgotten. In this way, the memory grows in knowledge rather than merely in volume.

\subsection{Tool-Native Memory as a System Service}

The 4D World Memory is exposed through the typed \nolinkurl{query_spatiotemporal_memory} interface rather than injected as an unstructured prompt. A query selects a replay time or world timeline and returns a causally bounded hierarchy, mapper-owned coordinates, current entity versions, capability declarations, and evidence handles. The same contract can be enriched with persistent objects, keyframes, captions, or embeddings without changing the controller-facing abstraction. As a result, heterogeneous tools consume one source of world authority: the language model decides \emph{what} to query and \emph{why}, while memory determines \emph{what has been observed}, \emph{where it exists}, and \emph{when that knowledge is valid}. This separation elevates 4D memory from a representation module to an operating-system primitive for persistent embodied cognition.

\section{Task-Conditioned Memory Retrieval}
\label{sec:memory_retrieval}


\subsection{Task-Conditioned Query Construction}
\label{subsec:retrieval_query}

A persistent world memory may contain thousands of entities and observations
collected across different locations and times. Retrieving globally by semantic
similarity is therefore insufficient for embodied tasks: a semantically relevant
object may be unreachable, an observation may no longer describe the current
world state, or a visually similar instance may be irrelevant to the active
subtask. Following Eq.~\eqref{eq:query_construction}, the Agent Controller
constructs the retrieval query from the user instruction, the active task stage,
the current robot state, and the remaining completion conditions.

The resulting query $\mathbf{q}_t$ can constrain several aspects of retrieval,
including target semantics, spatial scope, temporal range, desired entity state,
and, when available, visual evidence of the target. Memory retrieval is thus
conditioned not only on \emph{what} the agent is searching for, but also on
\emph{where} and \emph{when} the retrieved information should be valid for the
current task.


\subsection{Task-Conditioned Multimodal Retrieval}
\label{subsec:retrieval_impl}

Given $\mathbf{q}_t$, \dragentos{} retrieves candidate entities from persistent
memory before producing an executable spatial goal. For each stable entity
$v_i$, the retrieval index stores
\begin{equation}
    e_i =
    \left(
    i,\,
    d_i^{\mathrm{cur}},\,
    I_i^{\mathrm{crop}},\,
    I_i^{\mathrm{ctx}},\,
    \mathbf{p}_i,\,
    \boldsymbol{\xi}_i^{\mathrm{src}},\,
    \mathcal{P}_i
    \right),
    \label{eq:retrieval_record}
\end{equation}
where $i$ is the persistent entity identifier,
$d_i^{\mathrm{cur}}$ is its current structured description,
$I_i^{\mathrm{crop}}$ is the object-centric crop,
$I_i^{\mathrm{ctx}}$ is the corresponding full-frame observation,
$\mathbf{p}_i$ is the world coordinate maintained by the mapping system,
$\boldsymbol{\xi}_i^{\mathrm{src}}$ is the source observation pose, and
$\mathcal{P}_i$ stores the associated provenance.

The retrieval representation intentionally separates semantic evidence from
geometric metadata. Object crops used for embedding do not contain rendered
bounding-box overlays; overlays are retained only for later visual verification.
Likewise, source poses and world coordinates remain structured fields rather
than being encoded into the visual representation. This allows semantic
retrieval to rank entities without changing the geometry established by the
mapping and memory modules.

Each entity is encoded in the shared 3,584-dimensional QQMM-v2 embedding space
through three complementary channels: caption, crop, and context. The caption
channel represents category-level semantics and descriptive attributes; the
crop channel focuses on the appearance of the entity itself; and the context
channel retains surrounding scene information that can help distinguish
otherwise similar instances.

Let $\mathbf{z}_q$ be the normalized query embedding and
$\mathbf{z}_i^{(m)}$ the normalized representation of entity $i$ in channel
$m$. Channel-wise similarity is computed as
\begin{equation}
    s_i^{(m)}
    =
    \left\langle
    \mathbf{z}_q,
    \mathbf{z}_i^{(m)}
    \right\rangle,
    \qquad
    m\in
    \left\{
    \mathrm{cap},
    \mathrm{crop},
    \mathrm{ctx}
    \right\}.
    \label{eq:qqmm_similarity}
\end{equation}
The three channels are ranked independently. Scores that differ only within a
small numerical tolerance are treated as ties, avoiding artificial ranking
differences caused by instance ordering.

We combine the channel rankings using Weighted Reciprocal Rank Fusion (RRF).
Let $r_i^{(m)}$ denote the rank of entity $i$ in channel $m$. The fused score is
\begin{equation}
    S_i^{\mathrm{RRF}}
    =
    \sum_{m\in\mathcal{M}_q}
    \frac{w_m}{K_{\mathrm{RRF}} + r_i^{(m)}},
    \label{eq:weighted_rrf}
\end{equation}
where $K_{\mathrm{RRF}}=60$ and $\mathcal{M}_q$ denotes the active retrieval
channels. The default weights are
\begin{equation}
    \left(
    w_{\mathrm{cap}},
    w_{\mathrm{crop}},
    w_{\mathrm{ctx}}
    \right)
    =
    (1.0,\,1.0,\,0.5).
    \label{eq:rrf_weights}
\end{equation}
Using ranks rather than raw similarity values avoids requiring direct score
calibration across heterogeneous evidence channels. An entity that is
consistently ranked highly by multiple channels naturally receives a stronger
fused score.


\subsubsection{Relation-Aware QueryGraph}
\label{subsec:querygraph}

Semantic similarity alone is insufficient for queries that refer to an object
through another object, such as ``the chair next to the tall plant.'' For
supported relation expressions, \dragentos{} parses the query into a compact
QueryGraph containing a target category, an anchor category, and their spatial
relation.

For the \texttt{near} relation, candidate anchors are first retrieved
semantically. Given target entity $i$ and anchor $a$, their compatibility is
scored by
\begin{equation}
    S_{i,a}^{\mathrm{spatial}}
    =
    \alpha
    \frac{1}{r_a^{\mathrm{sem}}}
    +
    (1-\alpha)
    \frac{1}{
    1+
    \left\|
    \mathbf{p}_i^{xy}
    -
    \mathbf{p}_a^{xy}
    \right\|_2
    },
    \label{eq:spatial_relation_score}
\end{equation}
where $r_a^{\mathrm{sem}}$ is the semantic rank of anchor $a$,
$\mathbf{p}^{xy}$ denotes the horizontal world position, and
$\alpha=0.45$ in the current implementation. Each target is associated with
its highest-scoring compatible anchor,
\begin{equation}
    S_i^{\mathrm{spatial}}
    =
    \max_{a\in\mathcal{A}_q}
    S_{i,a}^{\mathrm{spatial}},
    \label{eq:best_spatial_anchor}
\end{equation}
where $\mathcal{A}_q$ is the retrieved anchor set.

The resulting $S_i^{\mathrm{spatial}}$ values are converted into a spatial
ranking $r_i^{(\mathrm{spatial})}$, which is then included as an additional
route in Eq.~\eqref{eq:weighted_rrf} with
$w_{\mathrm{spatial}}=1.0$.

The current QueryGraph supports only a bounded set of relation patterns.
If a relation cannot be parsed reliably, the system falls back to the
three-channel semantic retrieval procedure instead of imposing an uncertain
spatial constraint.


\subsection{Visual Candidate Verification and Goal Grounding}
\label{subsec:constrained_vlm}

The fused retrieval ranking provides a small set of candidate entities, but
semantic similarity alone may still confuse instances with similar appearance
or descriptions. We therefore use a VLM as a final visual verifier over the
top-ranked candidates. For each candidate, the verifier receives its
object crop, bounding-box visualization, contextual observation, and semantic
description. In the current implementation, at most the top five candidates
are examined.

Let
\begin{equation}
    \mathcal{C}_q =
    \left\{
    i_1,\ldots,i_{K_v}
    \right\}
    \label{eq:vlm_candidate_set}
\end{equation}
denote the candidate set produced by retrieval. The verifier either selects
one candidate or abstains:
\begin{equation}
    \widehat{i}
    \in
    \mathcal{C}_q \cup \{\varnothing\}.
    \label{eq:vlm_candidate_selection}
\end{equation}
An output that refers to an entity outside $\mathcal{C}_q$ is discarded.
This keeps the VLM verification stage grounded in entities already retrieved
from persistent memory.

Once an entity is confirmed, its navigation target is obtained directly from
the corresponding memory record:
\begin{equation}
    \mathbf{g}_{\mathrm{sem}}
    =
    \mathbf{p}_{\widehat{i}},
    \qquad
    \widehat{i}\neq\varnothing,
    \label{eq:semantic_goal_binding}
\end{equation}
where $\mathbf{p}_{\widehat{i}}$ is the world position associated with the
confirmed entity. The VLM therefore resolves instance-level ambiguity but
does not estimate the target position itself. Semantic verification and
geometric grounding remain separate: retrieval and visual reasoning identify
the target entity, while the spatial memory supplies the coordinate used by
the navigation module.


\section{Tool-Augmented Embodied Task Orchestration}
\label{sec:tool_orchestration}

\subsection{Goal Interpretation and Task Decomposition}
\label{subsec:goal_interpretation}

\paragraph{From instruction to completion conditions.}
Natural-language commands often specify an outcome without a feasible procedure. The Agent Controller uses a task interpreter $\mathcal{F}$ to normalize $\mathcal{T}$ into a goal $G$, constraints $\Omega$, a verifiable completion predicate $\chi$, and a dependency graph $\mathcal{D}_{\mathcal{T}}$:
\begin{align}
    (G,\Omega,\chi,\mathcal{D}_{\mathcal{T}})
    &= \mathcal{F}(\mathcal{T}),
    \label{eq:task_interpretation}\\
    \mathcal{D}_{\mathcal{T}}
    &= \left(\{u_j\}_{j=1}^{J},\prec,\{\chi_j\}_{j=1}^{J}\right),
    \label{eq:task_decomposition}
\end{align}
where $u_j$ is an executable or observable subtask, $\prec$ encodes prerequisite relations, and $\chi_j$ defines the evidence required to declare that subtask complete.

Explicit completion predicates align execution with the user's actual objective rather than a literal sequence of motions. They also expose infeasible steps, for which the controller can retrieve alternatives, explore, or request user input.

\subsection{Typed Tool Registry and World-Authority Separation}
\label{subsec:tool_registry}

\paragraph{Typed tool interface.}
\dragentos{} exposes memory, perception, planning, and inspection capabilities
through a common typed interface rather than embedding their implementations
inside the Agent Controller. Each registered tool is described by
\begin{equation}
    \mathrm{ToolSpec}
    =
    \left(
    n,\,
    \sigma_{\mathrm{in}},\,
    \mathcal{C},\,
    \nu
    \right),
    \label{eq:tool_spec}
\end{equation}
where $n$ is the tool name, $\sigma_{\mathrm{in}}$ is its structured input
schema, $\mathcal{C}$ specifies the controller modes in which the tool is
available, and $\nu$ denotes the schema version. A controller request is
represented as
\begin{equation}
    \mathrm{ToolCall}
    =
    \left(
    \mathrm{call\_id},\,
    n,\,
    \mathbf{a},\,
    \nu
    \right),
    \label{eq:tool_call}
\end{equation}
where $\mathbf{a}$ contains the typed arguments. Execution returns
\begin{equation}
    \mathrm{ToolResult}
    =
    \left(
    s,\,
    \mathbf{y},\,
    \mathcal{E},\,
    \ell,\,
    \varepsilon
    \right),
    \label{eq:tool_result}
\end{equation}
where $s$ is execution status, $\mathbf{y}$ is the structured payload,
$\mathcal{E}$ contains evidence references, $\ell$ records execution latency,
and $\varepsilon$ is a normalized error object when execution fails.

\paragraph{Registry execution semantics.}
Before a tool is invoked, the registry (i) resolves the registered tool name,
(ii) checks whether the current controller mode is permitted, (iii) validates
the arguments against the typed input schema, and (iv) accounts for the
available tool-call budget. Only after these checks does execution enter the
underlying worker. Failures are returned through the same
\texttt{ToolResult} contract rather than being exposed as unstructured
exceptions.

\paragraph{World-authority separation.}
A central design principle of \dragentos{} is that high-level reasoning does
not imply authority over the physical world model. The Agent Controller is
responsible for interpreting goals, selecting tools, and deciding how to
proceed from structured results, but source-grounded facts remain owned by the
modules that produce them. Specifically,
\begin{itemize}
    \item the \textbf{memory and mapping layers} own persistent entity
    identifiers, world coordinates, historical observations, and spatial
    relations;
    \item the \textbf{tool workers} own deterministic algorithmic outputs
    such as retrieval rankings and change evidence;
    \item the \textbf{execution runtime} owns authoritative robot motion,
    pose, observations, and collision feedback; and
    \item the \textbf{verification and memory-update path} determines when
    newly observed evidence is eligible to alter persistent state.
\end{itemize}

The controller therefore copies opaque identifiers and source-grounded
coordinates from tool outputs instead of synthesizing replacements. For
example, the VLM verification stage may select a legal entity identifier but
cannot create a new identifier or modify its coordinate. This separation
turns the Tool Registry into
more than a software dispatch mechanism: it defines the boundary between
probabilistic high-level reasoning and auditable world-state computation,
enabling heterogeneous perception, memory, navigation, and inspection modules
to participate in a common AgentOS loop.

\subsection{Memory-Grounded Tool Selection}
\label{subsec:tool_selection}

\paragraph{Standardized embodied tools.}
The Tool Manager exposes Memory Retrieval, semantic detection, exploration-state query, map query, route planning, local exploration, navigation, inspection, and interaction through standardized call and return schemas. Each tool consumes task and world-state arguments and returns a structured result with execution status and supporting evidence. Tools are thus selected using the ranked and verified context produced by Eqs.~\eqref{eq:weighted_rrf} and~\eqref{eq:constrained_vlm_output}, rather than being invoked in a predetermined order.

\paragraph{Decision criterion.}
At each round, the controller balances task progress, execution cost, safety risk, and the value of resolving uncertainty. For a candidate tool--action pair, we define the conceptual utility
\begin{equation}
\begin{split}
    J_t(z,\mathbf{a}) ={}&
    U_{\mathrm{task}}(z,\mathbf{a})
    +\lambda_i I_{\mathrm{gain}}(z,\mathbf{a})
    -\lambda_c C_{\mathrm{exec}}(z,\mathbf{a})
    -\lambda_r R_{\mathrm{risk}}(z,\mathbf{a}),
    \label{eq:tool_utility}
\end{split}
\end{equation}
and select
\begin{equation}
    (z_t^{*},\mathbf{a}_t^{*}) =
    \arg\max_{z\in\mathcal{Z},\,\mathbf{a}\in\mathcal{A}(z)}
    J_t(z,\mathbf{a}),
    \label{eq:tool_criterion}
\end{equation}
where $\mathcal{A}(z)$ is the argument or action space of tool $z$, $U_{\mathrm{task}}$ is expected progress toward $\chi$, $I_{\mathrm{gain}}$ is diagnostic information gain, $C_{\mathrm{exec}}$ is execution cost, and $R_{\mathrm{risk}}$ is task-dependent risk. The coefficients encode operational priorities.

Equation~\eqref{eq:tool_criterion} is a unifying decision rule implemented through controller reasoning and tool feedback. It is not intended to imply that the system explicitly solves an end-to-end differentiable optimization problem.

\subsection{Closed-Loop Execution and Replanning}
\label{subsec:closed_loop_execution}

\paragraph{Execution feedback.}
After executing $(z_t,\mathbf{a}_t)$, the controller receives a structured tool result together with new sensor observations. It re-evaluates the relevant $\chi_j$ and chooses among continuing the current plan, acquiring another observation, invoking a different tool, replanning, interacting with the user, or terminating.

\paragraph{Adaptive behavior.}
A blocked connection can update the route state and trigger replanning; an unknown place can trigger local exploration; and a remembered target can avoid unnecessary exploration. These behaviors are selected online from memory and execution feedback rather than encoded as separate scenario-specific pipelines.

\section{Conflict-Aware Reflection}
\label{sec:reflection}

An observation that disagrees with memory is informative but not automatically correct. Occlusion, a narrow field of view, imperfect association, or a transient obstacle can all resemble a persistent world change. Reflection converts such disagreements into explicit verification decisions.

\subsection{Memory--Observation Conflict Detection}
\label{subsec:conflict_detection}

\paragraph{Conflict dimensions.}
For an observed hypothesis $\widehat{v}_{i,t}$ matched to entity $v_i$, the system evaluates
\begin{equation}
\begin{split}
    C_t(i) ={}& \beta_{\mathrm{state}}\delta_{\mathrm{state}}
    +\beta_{\mathrm{pos}}\delta_{\mathrm{pos}}
    +\beta_{\mathrm{vis}}\delta_{\mathrm{vis}} \\
    &+\beta_{\mathrm{topo}}\delta_{\mathrm{topo}},
    \label{eq:conflict_score}
\end{split}
\end{equation}
where $\delta_{\mathrm{state}}$ denotes disagreement in an entity attribute, $\delta_{\mathrm{pos}}$ measures unexpected displacement, $\delta_{\mathrm{vis}}$ represents a visibility-aware absence test, and $\delta_{\mathrm{topo}}$ captures disagreement in reachability or connectivity. The nonnegative weights $\beta_{(\cdot)}$ adapt the check to the entity type.

\paragraph{Visibility-aware absence reasoning.}
Failure to observe an entity is not equivalent to its disappearance. The term $\delta_{\mathrm{vis}}$ is meaningful only when the remembered location should be observable under the current pose, field of view, occlusion, and sensing conditions. This distinction allows the same formulation to represent state changes, moved objects, temporary absence, suspected disappearance, and blocked routes without prematurely treating every mismatch as a permanent change.

\subsection{Active Evidence Acquisition and Reflective Decision}
\label{subsec:active_evidence}

\paragraph{Evidence construction.}
When $C_t(i)$ is material to the task or to a potential memory update, the controller constructs
\begin{equation}
    \mathcal{B}_t(i)=
    \mathcal{B}_{\mathrm{hist}}(i)
    \cup\mathcal{B}_{\mathrm{current}}(i)
    \cup\mathcal{B}_{\mathrm{active}}(i),
    \label{eq:evidence_set}
\end{equation}
where the three terms contain retrieved historical records, current multimodal observations, and deliberately acquired evidence, respectively.

\paragraph{Active verification.}
The controller may change its viewpoint, move locally, repeat detection, inspect the route or map, retrieve an older keyframe, or request user clarification. The information-gain term in Eq.~\eqref{eq:tool_criterion} makes these verification actions part of online task execution rather than an offline repair procedure.

\paragraph{Reflective outcomes.}
Reflection selects one of four semantic outcomes: retain the established state, mark it uncertain, record a provisional task-local state, or confirm a state change. The decision considers cross-view agreement, temporal repetition, modality diversity, visibility, source provenance, and the consequence of an incorrect update. A single surprising frame can therefore guide the next observation without immediately rewriting long-term knowledge.

\section{Evidence-Gated Memory Update}
\label{sec:memory_update}

\subsection{Evidence-Gated State Consolidation}
\label{subsec:evidence_gating}

\paragraph{Evidence confidence.}
Each proposed state change $\widehat{h}_{i,t}$ carries the evidence set from Eq.~\eqref{eq:evidence_set}. Let $r_b\in[0,1]$ denote the reliability of evidence item $b$, $a_b\in[0,1]$ its agreement with the proposed change, and $w_b\geq0$ its modality- and source-dependent weight. We summarize corroboration as
\begin{equation}
    C_{\mathrm{evidence}}(\mathcal{B}_t(i))
    = \frac{\sum_{b\in\mathcal{B}_t(i)} w_b r_b a_b}
    {\sum_{b\in\mathcal{B}_t(i)} w_b+\epsilon},
    \label{eq:evidence_confidence}
\end{equation}
where $\epsilon>0$ prevents an undefined score for an empty evidence set. This deterministic aggregation represents evidential support and is not presented as a learned probabilistic model.

\paragraph{Long-term update gate.}
Let $r_t^{\mathrm{conf}}(i)\in\{0,1\}$ indicate whether the conflict associated with entity $i$ has been examined using sufficient task-relevant evidence. The system commits a proposed change to long-term memory only when
\begin{equation}
    g_t(i)=\mathbb{I}\!\left[
    C_{\mathrm{evidence}}(\mathcal{B}_t(i))\geq\eta_i
    \ \land\ r_t^{\mathrm{conf}}(i)=1
    \right],
    \label{eq:update_gate}
\end{equation}
where $\eta_i$ is an entity- and consequence-aware threshold. High-impact changes can therefore require stronger corroboration than transient task states.

\paragraph{Version-preserving update.}
Memory evolves according to
\begin{equation}
    \mathcal{M}_{t+1}=\mathcal{U}\!\left(
    \mathcal{M}_t,\widehat{h}_{i,t},\mathcal{B}_t(i),g_t(i)
    \right),
    \label{eq:memory_update}
\end{equation}
where $\mathcal{U}$ is applied to every affected entity. If $g_t(i)=0$, the current long-term state is retained while the new evidence may remain as an uncertain annotation or provisional task-memory entry. If $g_t(i)=1$, $\widehat{h}_{i,t}$ is appended as a confirmed version with its change time, confidence, and provenance, and the entity's current-state pointer advances. Earlier versions are never overwritten.

Newly discovered entities follow the same evidence-aware consolidation principle before becoming persistent facts. This mechanism separates durable world knowledge, dynamic conditions, and current-task hypotheses while preserving the evidence required to audit later changes.

\subsection{Persistent Online Cognition Loop}
\label{subsec:online_loop}

\paragraph{Online procedure.}
The complete execution loop proceeds as follows:
\begin{enumerate}
    \item interpret task $\mathcal{T}$ into $(G,\Omega,\chi)$ and construct $\mathcal{D}_{\mathcal{T}}$;
    \item acquire and spatially ground the available observation $\mathbf{o}_t$;
    \item construct $\mathbf{q}_t$ and retrieve $\mathcal{R}(\mathcal{M}_t,\mathbf{q}_t)$;
    \item select and execute $(z_t,\mathbf{a}_t)$ using retrieved memory and tool feedback;
    \item detect conflicts between new evidence and $\mathcal{M}_t$;
    \item acquire active evidence and reflect when a conflict remains unresolved and task relevant;
    \item apply the Evidence-Gated Memory Update to obtain $\mathcal{M}_{t+1}$; and
    \item re-evaluate completion predicates and replan or terminate accordingly.
\end{enumerate}

\paragraph{Unified operation across tasks.}
The loop contains no scenario-specific branch. Differences among large-scale navigation, unknown-space exploration, and repeated inspection enter through the task goal, memory scale, and available tool set. In every case, execution supplies new evidence, Reflection determines what that evidence warrants, and Evidence-Gated Memory Update makes confirmed experience reusable by later tasks.

The resulting perception--memory--reasoning--action--reflection--update cycle is the defining system property of \dragentos{}. A static map remains a useful geometric layer, but it is embedded within a task-conditioned and versioned world model whose contents can be questioned, verified, and responsibly revised during long-term operation.
